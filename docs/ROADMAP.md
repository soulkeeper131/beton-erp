# Beton ERP — Backlog / Roadmap

> Действителен backlog за развитие. Приоритети: **P0** критично, **P1** високо, **P2** средно, **P3** ниско.
> Обновявай статуса с `[x]` при завършване. Детайлната обосновка е в `docs/OVERVIEW.md`, раздел 11.

## P0 — Съответствие и критични рискове

- [ ] **Наредба Н-18 / СУПТО съответствие**
  - **Проблем:** издадени фактури/актове могат да се редактират свободно — фискален риск за българския пазар.
  - **Обхват:** номерация с фискална памет, lock на издадени документи (само сторно/кредитно известие), одит trail за всяко издаване.
  - **Референция:** skill `bulgarian-fiscal-compliance`.
  - **Acceptance:** издаден документ не може да се трие/редактира; промените минават през сторно с одит.

---

## P1 — Завършване на ядрото (мъртви таблици)

- [ ] **Складова книга (`material_deliveries`)**
  - **Проблем:** таблицата е в схемата, но няма никакъв код. Складът е статичен (`materials.quantity` ръчно).
  - **Обхват:** приход/разход на материали, история, връзка с актове, ниски наличности.
  - **Acceptance:** може да се регистрира доставка и разход; наличността се изчислява автоматично.

- [ ] **Работници в акт (`act_workers`)**
  - **Проблем:** таблицата се чете само в PDF, няма UI/API за въвеждане.
  - **Обхват:** добавяне на работници към акт (часове, ставки, тотал), CRUD в `/pourings/[id]`, изчисление в PDF.
  - **Acceptance:** акт може да съдържа работници и сумите им да излизат в PDF.

- [ ] **Материали в акт (`act_materials`)**
  - **Проблем:** напълно мъртва таблица.
  - **Обхват:** връзка на изразходени материали към акт + приспадане от склада.
  - **Acceptance:** при завършен акт материалите се изваждат от наличността.

- [ ] **Явки и заплати (`worker_attendance`)**
  - **Проблем:** само dashboard чете — няма CRUD.
  - **Обхват:** ежедневни явки, извънреден труд, аванси, месечна справка за заплати.
  - **Acceptance:** бригадир/админ въвежда явки; излиза месечна ведомост.

- [ ] **Разширяване на ролите** (`manager`, `brigadir`)
  - **Проблем:** README споменава 4 роли, реално са `admin`/`employee`.
  - **Обхват:** роли в схемата + middleware/frontend guard; бригадир — само календар + снимки на обекта.
  - **Acceptance:** бригадир вижда само позволените модули.

## P2 — Отчетност и операции

- [ ] **Разширени справки** — печалба по обект/клиент, разход по машина, справка за материали, детайлно „офертирано vs. актувано".
- [ ] **Автоматични нотификации** — изтичащи винетки/ГО/прегледи (данните са в `machines`), ниски наличности, неплатени фактури (имейл + в приложението).
- [ ] **Периодични оферти/фактури** — месечни доставки, договорни цени, авто-генериране.

## P3 — Качество и мащаб

- [ ] **Автоматични тестове** — минимум API smoke + PDF генерация (в момента 0 теста).
- [ ] **Offsite backup** — криптиран backup към S3/Drive (в момента само локална ротация).
- [ ] **Schema drift изчистване** — уеднаквяване на `schema.ts` ↔ `index.ts` миграциите.
- [ ] **PWA push notifications** — за наряди и срокове.
- [ ] **Многоезичност** — ниско приоритетно (вътрешен инструмент).
