# Beton ERP — Backlog / Roadmap

> Действителен backlog за развитие. Приоритети: **P0** критично, **P1** средно, **P2** ниско.
> Обновявай статуса с `[x]` при завършване. Детайлната обосновка е в `docs/OVERVIEW.md`, раздел 11.

---

> ⚠️ **Н-18 / фискални устройства не са в обхвата** — фирмата не издава касови бележки и не приема кеш от физически лица; работи по фактури (ЗДДС) + банков превод. Фокусът е да работи ERP-то.

## P0 — Завършване на ядрото (мъртви таблици)

- [x] **Складова книга (`material_deliveries`)**
  - **Проблем:** таблицата е в схемата, но няма никакъв код. Складът е статичен (`materials.quantity` ръчно).
  - **Обхват:** приход/разход на материали, история, връзка с актове, ниски наличности.
  - **Acceptance:** може да се регистрира доставка и разход; наличността се изчислява автоматично.

- [x] **Работници в акт (`act_workers`)**
  - **Проблем:** таблицата се чете само в PDF, няма UI/API за въвеждане.
  - **Обхват:** добавяне на работници към акт (часове, ставки, тотал), CRUD в `/pourings/[id]`, изчисление в PDF.
  - **Acceptance:** акт може да съдържа работници и сумите им да излизат в PDF.

- [x] **Материали в акт (`act_materials`)**
  - **Проблем:** напълно мъртва таблица.
  - **Обхват:** връзка на изразходени материали към акт + приспадане от склада.
  - **Acceptance:** при завършен акт материалите се изваждат от наличността.

- [x] **Явки и заплати (`worker_attendance`)**
  - **Проблем:** само dashboard чете — няма CRUD.
  - **Обхват:** ежедневни явки, извънреден труд, аванси, месечна справка за заплати.
  - **Acceptance:** бригадир/админ въвежда явки; излиза месечна ведомост.

- [x] **Разширяване на ролите** (`manager`, `brigadir`)
  - **Проблем:** README споменава 4 роли, реално са `admin`/`employee`.
  - **Обхват:** роли в схемата + middleware/frontend guard; бригадир — само календар + снимки на обекта.
  - **Acceptance:** бригадир вижда само позволените модули.

## Как се работи с този backlog

1. Вземи задача с най-висок приоритет отгоре-надолу.
2. Пиши план в `.hermes/plans/YYYY-MM-DD_<slug>.md` (конвенцията вече съществува).
3. Имплементирай през съществуващите патърни (force-dynamic, DejaVu PDF, EIK debounce — виж `docs/OVERVIEW.md`, раздел 10).
4. Обнови статуса тук с `[x]` и commit.
